A preflight gate for agent tool calls

How big
is this?

An agent asks to do one thing. That one thing turns out to be a million things. Nobody finds out until after.

neti resolves what a call will actually touch before it runs, compares that count to a ceiling you declared, and stops it when it does not fit.

The call

One string, four hundred people

remove_group_members(group: "engineering-all")

Your policy engine sees a string on an allowlist, and the string is allowed. neti sees 412 people losing access to 9 applications — and stops the call, because you declared a ceiling of 200.

Alignment, authorization, provenance, sandboxing, anomaly detection and rollback each answer a different question. None of them answers this one.

The decision

A static integer comparison

There is no threshold to tune, no model to drift in the decision path, and nothing to calibrate on a corpus. A resolver turns the argument into a count; the count is compared against bands you committed to a file; the verdicts join, most-restrictive-wins.

  • ALLOWIt fits. Nothing is said, so your existing permission rules keep working exactly as they were.
  • FLAGIt runs, and it is recorded as notable.
  • CONFIRMSomebody other than the agent's operator should decide this one.
  • BLOCKIt does not run, and the reason carries the number.

Two properties make the verdict sound, and everything rests on them. No resolver may return 0 for something it could not reach — an unreachable target and an empty one are opposite situations with the same number. And anything capped or estimated reports a lower bound, which can block soundly and can never allow, so the targets too large to count are exactly the ones that cannot slip through quietly.

Twelve seams · no code change

Where it plugs in

Every runtime has one place where a request becomes an execution. neti sits at that place — so a blocked call comes back to the model as a tool result with the number in it, never an exception that kills the run.

The only seam that can see a harness's built-in tools — Read, Edit, Glob, Grep, Write. No proxy can: they never travel over a protocol. This is also where the gate is most effective, gating 6 of 10 built-ins against 25 of 160 MCP tools.

What it does not do

neti answers how big, not whether this is a good idea. The holes are numbered so that tests and write-ups can cite them, and the numbers are published whether or not they flatter.

  • A per-call gate cannot see four thousand individual sends unless you declare a session budget.
  • Shell commands are not sized — what rm -rf $X deletes is a grammar, not a value, and a gate that guesses is worse than no gate.
  • Against 170 real tool schemas the rule table gates 31 and leaves 401 parameters unclaimed. Most genuinely are not sets. Some are, and those are open issues.

Every one of these is written down in SCOPE.md before you install anything, alongside the sentences this project does not say.

neti cloud

When a confirm
needs an actual human

A confirm band means somebody other than the agent's operator should decide this one. On one machine there is nobody to ask, so the gate stops the call and says so. That is correct, and it is what a free install will keep doing forever.

The hosted tier is the somewhere that question can go.

  1. The call stops 500 recipients against a ceiling of 50. The agent is told an approval is pending, with its id, and to retry this exact call once it is granted.
  2. A reviewer is asked Not the operator, and not the agent. They see the number, the ceiling, and the evidence the verdict was derived from — nothing else is needed to decide.
  3. They answer Approve or deny, against their name. The answer is recorded as who said yes, not as a second opinion about whether the call was too big.
  4. The agent retries The same call, once. The run continues from where it stopped rather than starting again or routing around.

What approving actually authorises

The narrowest thing it can, because a grant that means more than the person thought is the failure mode that matters here. Every one of these is a test in the public repository.

  • This call once. Bound to these exact arguments under this exact policy.
  • Spent on redemption. A grant cannot authorise a second call.
  • Expiring. An answer nobody acted on stops being an answer.
  • Refused if the target grew. If the group is bigger than when a human looked at it, the grant no longer applies.
Fleet

Every agent, one place

One policy version across every machine, signed and pinned by digest, instead of a file per laptop that drifts. Session budgets that survive a restart. And per-machine record chains anchored centrally, so a deleted local file becomes detectable rather than simply gone.

Your records stay yours. The local NDJSON is the source of truth. A control plane anchors it; it is not an authority over it, and neti verify works with the network unplugged, forever.

Licensing

Can one machine do this?

That is the whole rule, and it decides every case. Enforcement runs on one machine, so blocking is free — forever, with nothing withheld, nothing time-limited, and no telemetry. A second person approving a call does not run on one machine, so it is not.

Two things that stay true when you pay

The gate takes on no new availability risk. If the control plane is unreachable, absent or unpaid, it behaves exactly as the free tier — a control plane can only ever make a decision more permissive, and only through a named human.

The client is open source. neti.cloud — the approver, the credential file, the wire format — is Apache-2.0 in the public repository, along with the tests pinning every property above. Read the protocol, write your own server, hold it to those tests. What you pay for is a server that is running, not a secret about how to talk to it.
